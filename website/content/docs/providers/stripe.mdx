danwo's Stripe emulator answers Stripe's API and its hosted Checkout page. The official
`stripe` package works against it unchanged, and your app keeps its own `sk_test_` key.

This page covers payments and Checkout. Subscriptions and invoices have their own page,
[Stripe billing](/docs/providers/stripe-billing), and so do the browser's
[Stripe.js and test cards](/docs/providers/stripe-js).

## Set up

Add `stripeService` to your environment:

```ts title="danwo.config.ts"
import { appEnvironment, defineConfig, stripeService } from "@danwo/sdk"

export default defineConfig({
  testDir: "tests",
  readiness: { mode: "page+backend", settle: true },
  environment: () =>
    appEnvironment({
      app: { command: "npm run dev", url: "http://localhost:3000" },
      services: [stripeService()],
    }),
})
```

Your app needs nothing new. Any `sk_test_` key is accepted, so keep the one in your `.env`.
`settle: true` makes each step wait until Stripe's webhooks have reached your app.

## Seed it

The seed is a function: it runs at the start and before every test.

```ts title="danwo.config.ts · the seed"
stripeService({
  seed: () => ({
    customers: [{ id: "cus_ada", email: "ada@example.com", name: "Ada" }],
    products: [{ name: "Credits" }],
    prices: [{ product_name: "Credits", unit_amount: 500, currency: "usd", lookup_key: "credits" }],
    webhookEndpoints: [
      {
        url: "http://localhost:3000/api/webhooks/stripe",
        events: ["checkout.session.completed"],
        secret: "whsec_test",
      },
    ],
  }),
})
```

| Field                         | What it seeds                                                                  |
| ----------------------------- | ------------------------------------------------------------------------------ |
| `customers`                   | Customers, with your own ids if you give them.                                 |
| `products`                    | Products, named so prices can refer to them.                                   |
| `prices`                      | One-off or recurring prices, by `product_name`, with an optional `lookup_key`. |
| `webhookEndpoints`            | Where webhooks go, which events, and the signing secret.                       |
| `paymentMethodConfigurations` | Which payment methods Checkout offers.                                         |

## Use it in a test

The `stripe` fixture is the emulator. Ask it what happened with Stripe's own API, through
`stripe.fetch`:

```ts title="tests/buy.danwo.ts"
import { type StripeFixtures, test as base } from "@danwo/sdk"

const test = base.extend<StripeFixtures>()

test("pays for credits once", async ({ app, screen, expect, stripe }) => {
  await app.open("/")
  await screen.getByRole("button", { name: "Buy 500 credits" }).click()
  await screen.getByTestId("checkout-pay").click()
  await expect(screen.getByText("Credits: 500")).toBeVisible()

  const answer = await stripe.fetch(
    new Request("https://api.stripe.com/v1/checkout/sessions?payment_status=paid", {
      headers: { authorization: "Bearer sk_test_any" },
    }),
  )
  const { data } = await answer.json()

  expect(data).toHaveLength(1)
})
```

On the emulator's Checkout page, `checkout-pay` pays and `checkout-cancel` goes back to your
`cancel_url`.

## What's covered

| Area                | Covered                                                            |
| ------------------- | ------------------------------------------------------------------ |
| Customers           | Create, read, update, delete and list them, and customer sessions. |
| Products and prices | One-off and recurring prices, found by lookup key.                 |
| Payment intents     | The whole life of a payment: create, confirm, cancel.              |
| Payment methods     | Saved cards, attached to and detached from customers.              |
| Charges and refunds | Charges, and full or partial refunds.                              |
| Checkout            | Sessions in payment or subscription mode, the hosted page, expiry. |
| Webhook endpoints   | Endpoints, and signed deliveries with retries.                     |
| Requests            | Idempotency keys, expansion and Stripe's error shapes.             |

## Faults

| Call                                          | Faults the matrix tries                                                |
| --------------------------------------------- | ---------------------------------------------------------------------- |
| A write, such as `POST /v1/checkout/sessions` | 500, 429 rate limit, connection reset, answer lost after Stripe acted  |
| A read, such as `GET /v1/customers/:id`       | 500, 429 rate limit, connection reset                                  |
| Every webhook delivery                        | arrives twice, arrives 10 minutes late, forged signature, 1 hour stale |

The error bodies are Stripe's, so the SDK raises `StripeAPIError` or `StripeRateLimitError` just
as it would for real.

## Webhooks

Deliveries carry a `Stripe-Signature` header made with the endpoint's `secret`, so
`stripe.webhooks.constructEvent` accepts them. A failed delivery is retried after 5 minutes, 30
minutes and 2 hours, on the emulator's clock.

| Event                           | Sent when                                 |
| ------------------------------- | ----------------------------------------- |
| `checkout.session.completed`    | A customer pays on the Checkout page.     |
| `checkout.session.expired`      | A session expires unpaid.                 |
| `payment_intent.succeeded`      | A payment goes through.                   |
| `payment_intent.payment_failed` | A payment is declined.                    |
| `charge.refunded`               | A charge is refunded, in full or in part. |
| `customer.created`              | A customer is created.                    |

The billing events are on [Stripe billing](/docs/providers/stripe-billing#webhooks).

## Fidelity

**Live.** `danwo fidelity stripe` runs 11 scenarios against a Stripe test-mode account and
compares each answer's shape. All 11 match. Checkout differs where the account has Stripe Tax
turned on, which is recorded as a known difference.
