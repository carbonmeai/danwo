The **replay cache** keeps a recording of every agent step that passed. The next run replays that
recording instead of asking the model, so reruns are fast, free and give the same answer every
time.

<ReplayFlow />

## How a step is recorded

The first time an `agent.act` passes, danwo keeps what the model did. It keeps each element it
acted on, described by what it is (its role, name, label and text), not by its position. It also
keeps what the step changed, on the page and behind it.

On the next run, danwo finds each element again by that description and repeats the actions.

## Read the cache line

Every run with agent steps prints a `cache:` line, counting what each step came to:

```text
cache: 12 replayed · 1 relocated · 1 handed off · 0 missed
```

| Outcome      | What happened                                                         |
| ------------ | --------------------------------------------------------------------- |
| `replayed`   | The recording replayed as recorded, with no model.                    |
| `relocated`  | It replayed, but an element was found somewhere other than recorded.  |
| `handed-off` | The replay stopped matching, so the model took the step over.         |
| `missed`     | There was no recording, so the model ran.                             |
| `stale`      | A recording of this step exists under another key, so it wasn't used. |
| `diverged`   | Under strict replay, the recording no longer replays.                 |
| `off`        | The session has no cache.                                             |

A `handed-off` step is recorded afresh once it passes, so the next run replays again.

## When a recording goes stale

A step's recording is keyed by its instruction and its options. Change the instruction, its
`params` names, or the page it starts on, and the old recording no longer applies:

```text
cache: 3 replayed · 0 relocated · 0 handed off · 0 missed · 1 stale
```

Rerun the test to record the new version. The failure page names what changed.

## Replay in CI

Commit the cache folder, set by `cache.dir` in your config, so CI replays with no model calls:

```ts title="danwo.config.ts · the cache"
cache: { dir: ".danwo-cache" },
```

<Callout type="warn">
  In CI the cache is read-only: steps replay from it, but nothing new is written, so CI leaves the
  cache as you committed it. A step that misses there calls the model on every run. Rerun it
  locally, check it, and commit the new recording.
</Callout>

## Manage recordings

```sh
npx danwo cache ls
npx danwo cache stats
npx danwo cache clear
```

`ls` lists the recordings, `stats` counts them by outcome, and `clear` deletes them so every step
records afresh.
