## Changed

- **danwo's own proxy.** The proxy that routes your app's calls and injects faults is now danwo's
  own code, with no dependencies. A web project installs 54 packages and 71 MB, down from 249
  packages and 123 MB, and `npm audit` finds nothing. The basic-ftp advisory is gone with it.
- **Yjs only for Tiptap.** `yjs` and `y-protocols` are optional now, and only the Tiptap emulator
  loads them. An app that uses Tiptap's collaboration has them already; one that doesn't is told
  `npm install -D yjs y-protocols`. See [Tiptap](/docs/providers/tiptap).
- The proxy prints nothing when a connection drops. Set `DANWO_DEBUG=proxy` to see each call it
  handles and why one failed.

## New

- **HTTP/2 and gRPC.** Clients that speak only HTTP/2 now go through danwo's proxy. That covers
  gRPC: Google Cloud's client libraries such as Firestore and Pub/Sub, Temporal, and your own gRPC
  services. Streams flow both ways as they arrive, and trailers such as `grpc-status` reach your
  app. Plain-text gRPC works too.
- Browsers and SDKs that offer both HTTP/1.1 and HTTP/2 still get HTTP/1.1, so nothing changes
  for them.
- A fault on an HTTP/2 call hits that one stream. A `reset` resets the stream, and the other
  calls on the same connection carry on.
- An emulator can stream a gRPC call both ways, and send its `grpc-status` once its stream ends
  with `withTrailers`.
- If a real server closes a connection just as a call goes out, the proxy sends the call again on
  a fresh one.
- gRPC apps in Python, Ruby and PHP trust danwo's CA with no change: danwo sets
  `GRPC_DEFAULT_SSL_ROOTS_FILE_PATH`. See [Apps in other languages](/docs/other-languages#grpc).

## Fixed

- Bachs' emulator works with `@bachs/sdk` 2.0, including `listAll()` paging through products and
  payments.
- Flutterwave's fidelity check matches its live bank list again.
- Bachs' emulator settles a payment even when its timer fires a moment early, so the payment's
  webhook is never lost on a busy machine.
- A call to an app on a `*.localhost` name is checked for a listener at the address it's dialled
  at, so it works where no resolver knows the name.
- danwo's CA can sign only the certificates it serves, never another CA.
